### 2.1 材料要求的"同时遵守公共约束"

材料 CR-01 明确："该规则同时遵守名额限制、活动开始时间和重复报名等公共约束。"这三条各有独立用例：

| 约束 | 测试 | 断言 |
|---|---|---|
| 名额限制 | `test_grade_limit_still_respects_capacity` | 年级符合但名额已满 → `CAPACITY_FULL` |
| 活动开始时间 | `test_grade_limit_still_respects_started_activity` | 活动已开始 → `ACTIVITY_STARTED` |
| 重复报名 | `test_grade_limit_still_blocks_duplicate_active_registration` | 二次提交 → `DUPLICATE_ACTIVE` |

### 2.2 材料要求的"原有行为不得改变"

| 场景 | 测试 | 断言 |
|---|---|---|
| 未设年级限定的活动 | `test_activity_without_grade_limit_keeps_original_behavior` | 四个年级全部直接报名成功 |
| 审核型 + 年级限定 | `test_review_policy_combined_with_grade_limit` | 符合年级 → `PENDING`；不符合 → 拒绝（验证两个变化轴正交） |
| 学生不存在 / 活动不存在 | `test_unknown_student_and_activity_keep_original_error_codes` | 错误码仍是 `STUDENT_NOT_FOUND` / `ACTIVITY_NOT_FOUND` |
| 未登记年级 | `test_student_without_registered_grade_is_blocked` | `GRADE_NOT_REGISTERED`，提示引导补录 |

### 2.3 规则解析的边界值

`test_parse_grade_limit_accepts_common_separators`（8 组参数化）+ `test_parse_grade_limit_rejects_out_of_range`（4 组）+ `test_grade_rule_label_is_human_readable`：
覆盖 `,` `;` `、` 空格四种分隔符、去重、空值、越界（0/5）、非数字（abc/2,x）、中文标签生成。

## 3. CR-02 变更测试映射

| 材料条目 | 输入 | 材料期望 | 对应测试 | 断言要点 |
|---|---|---|---|---|
| CR2-01 | 直接报名通过 | 站内消息和模拟邮件均有记录 | `test_cr2_01_direct_registration_writes_both_channels` | `message` 1 条且含"报名成功"；`email_delivery` 1 条 `SENT` |
| CR2-02 | 审核批准或拒绝 | 两种渠道记录对应结果 | `test_cr2_02_approve_sends_approval_mail`、`test_cr2_02_reject_sends_rejection_mail` | 邮件主题分别含"已通过"/"未通过"；站内消息同步 |
| CR2-03 | 模拟邮件发送失败 | 报名状态正确、错误有日志 | `test_cr2_03_mail_failure_keeps_registration_and_logs_error` | 报名 `APPROVED` 且已落库；站内消息不受影响；`email_delivery` 记 `FAILED`+错误；`notify_outbox` 有 `mock_email` 的 `FAILED` |
| CR2-04 | 重复提交同一业务动作 | 不应重复生成多份相同通知 | `test_cr2_04_repeated_business_action_does_not_duplicate_mail`、`test_cr2_04_same_event_published_twice_sends_once` | 业务层：第二次被 `DUPLICATE_ACTIVE` 拦住，邮件仍 1 封；通知层：同一 event 发布两次，`email_delivery` 仍 1 行 |
| CR2-05 | 重跑原有用例 | 原有功能保持通过 | 同 CR1-05，25 例 | 见 §4 |

### 3.1 材料要求的"记录收件人、主题、内容、状态与时间"

`test_cr2_01_email_records_all_required_fields` 逐列核对：

| 材料字段 | 落点 | 断言 |
|---|---|---|
| 收件人 | `email_delivery.address` | `s2@campus.edu.cn` |
| 主题 | `email_delivery.subject` | 含活动名 |
| 内容 | `email_delivery.body` | 含学生姓名与活动名 |
| 状态 | `email_delivery.status` | `SENT` |
| 时间 | `email_delivery.attempted_at` | 非空 |
| （附加）可追溯 | `email_delivery.event_id` | 非空，可关联到业务事件 |

### 3.2 边界

| 场景 | 测试 | 结论 |
|---|---|---|
| 取消报名是否发邮件 | `test_cr2_02_cancel_does_not_send_mail` | 不发。材料只要求"报名通过、审核通过或拒绝"三类 |
| 订阅者集合是否稳定 | `test_extended_bus_keeps_channel_set_stable` | 恰为 `{in_app, mock_email, audit}`，防止重复订阅导致重复发信 |
